# Privacy boundaries — source contract, runtime unverified

Raw report values and selected folder files are read in the parsing Web Worker. It masks known report values across report/context fields, builds the leak index and returns guarded findings plus numeric-only hashed guard state. Worker termination and reference release are designed boundaries, not measured memory zeroization. No raw report is intended to enter page state, IndexedDB, model requests or cloud rows. Browser capture and storage inspection remain deferred.

The guard rejects known six-character substrings and whole nonempty shorter values at token boundaries. Only a listed provider prefix at its kept masked position is exempt; digests have no exemption. Hash or ordinary-text collisions fail closed and can make otherwise useful output unavailable. Generic detection of unreported credential-like strings is heuristic and cannot guarantee detection of unknown secrets. Bounded matching/index overflow fails closed or routes affected findings to review. `serializeSafe` is the outbound check for state, notes, persistence, inference and export; error text is fixed/empty rather than raw exception content.

The project identity salt is random and stored locally in IndexedDB to stabilize keyed identities. It differs from the session-only guard salt/index, which is never persisted. Reload requires re-import before guarded actions. Clearing browser data loses stable identities. Setup offers an explicit local private-identity backup after re-import; it contains the private salt and is not an ordinary report export. Keep it private. No automatic cross-device restore is provided. Evaluation uses its own ignored `.eval-local/` identity, with fresh in-memory guards.

Local append-only sanitized decisions and immutable audit cohorts persist in IndexedDB. Notes are explicit user input and checked by the fresh guard; do not put unrelated confidential information in notes. Four report downloads are dry runs: masked JSON, CSV, Markdown and approved current gitleaks ignore entries. Nothing edits scanner reports, repositories, credentials or upstream suppressions.

Cloud and inference consent are separate, off by default and session-only. Account/store changes clear the imported session; old local decisions are not bulk-uploaded. Cloud finding IDs are keyed opaque account/project-scoped IDs rather than scanner fingerprints. Cloud rulings contain binding hashes, decisions and guarded notes; summaries contain counts/provenance, not source paths or lines. User-scoped RLS and append-only grants are written but unexecuted. Identity salts, raw values and guard state are excluded from cloud schemas.

Optional inference sends guarded masked views (including selected basename/context information) only after explicit consent, authentication and fresh import. Treat remaining context as potentially sensitive. Server-owned provider URLs, models, dated prices and caps are required. Each attempt reserves/claims budget before dispatch; retries and semantic screens count. Minimal ledger metadata retains owner, request/payload hash, model/provider, units and reservation/settlement costs. Unknown or estimated cost remains distinguishable; run summary cost is NULL unless complete actual usage is known. Provider retention policies and live wire behavior require owner verification before activation.

Caches/results distinguish scripted replay from live work and bind prompt/config/model/data/split lineage. No measured accuracy, latency, privacy, cost or generalisation claim exists. CredData tooling reads only explicitly selected normalized metadata CSVs under a resolved local root, never referenced source files; committed output excludes source paths/content/values. See the manifest contract and deferred-validation ledger.
